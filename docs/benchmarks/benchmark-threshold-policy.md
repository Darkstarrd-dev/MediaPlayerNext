# Benchmark 阈值策略（首版）

## 1. 目标

建立统一的 benchmark compare + threshold 判断口径，避免仅凭体感判断回归。

## 2. 适用范围

- scan / archive / thumbnail / playback / sidecar 等高频路径
- 重大重构或依赖升级后的回归验证

## 3. 基线记录要求

- 每个场景至少记录：
  - 样本规模
  - 机器环境（CPU / 内存 / OS）
  - 执行命令
  - 指标（耗时 / 吞吐 / 失败率）
- 基线数据与本轮结果必须同目录可追溯

## 4. 阈值建议（首版）

- `p50`/`p95` 耗时回退超过 `15%`：告警
- 吞吐下降超过 `10%`：告警
- 失败率上升到 `>1%`：阻断

## 5. 发布前要求

- 发布前至少一轮关键路径 benchmark compare
- 结果必须引用具体产物路径，不能仅口头结论
- 若触发告警，需在 Go/No-Go 报告给出风险接受或修复结论
